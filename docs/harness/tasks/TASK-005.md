# TASK-005: 공통 관측 명령과 설정 기반 증거 폴더

## Goal

메모리·CPU·교착상태 관측을 하나의 사용자 명령에서 선택하고, 실행 증거 폴더 이름에서 시각과 세 설정값을 식별한다.

## Context

- 2026-10-27 최초 요청: `128_40_false-XXXXXX` 형태의 실행 폴더, 한 가지 사용자 명령, 앱 종료는 사용자 수동 처리. 이후 사용자 피드백으로 이름순 실행 시각 정렬이 필요해 `YYMMDD-HHMMSS_128_40_false-XXXXXX` 형식으로 변경 승인받았다.
- 승인 전 읽기 전용 Implementer 검토에서 기존 메모리 자동 비교는 자연 종료까지 기다리므로 40% 정상 경로에서 끝나지 않을 수 있음을 확인했다. 이번 메모리 관측은 시간 제한이 있는 단일 실행이며 두 메모리 설정은 사용자가 순서대로 실행한다.
- 난이도: MEDIUM. 공통 저장 경로와 관측 종료 처리에 영향이 있다.
- 추천 모델: GPT-6 Sol / Medium (Implementer·Reviewer). 모델 지정은 [MODEL_POLICY.md](../MODEL_POLICY.md)를 따른다.
- Review 예상: REQUIRED — 공통 파일 경로 생성과 신규 관측 종료·수집 정리 흐름.
- Step 및 구현 계획 승인: 사용자의 “그럼 일단 kill은 내가 직접할게. 수정 시작”으로 앞서 제시한 네 파일 계획과 수동 앱 종료 경계를 승인받았다. 종료 자동화는 범위 밖이다.
- 변경 기준점: `4335e76`, 작업 트리 clean 확인. 과거 `runs/` 증거는 Git 제외이며 원본 보존.
- 후속 사용자 승인: “그럼 그렇게 해봐. 날짜시간순으로 정렬되게 그 형식으로 수정. 현재 runs 안에 있는 폴더 이름도 그와같이 변경해놔”. 새 실행 폴더 생성 규칙과 현재 존재하는 7개 과거 증거 폴더의 rename, 그 7개를 가리키는 저장소 문서 링크 갱신을 포함한다. 앱 로그 안의 당시 절대 경로 문자열은 원본 증거로 보존한다.

## Execution State

- 현재 단계: 기본 구현·REQUIRED 리뷰·승인 수정·독립 재검토와 시각 접두어·당시 7개 폴더 이동·링크 변경 독립 리뷰 완료. 사용자 실행 검증 대기.
- 승인 범위: [준비 도구](../../../prepare-env.sh)의 폴더 이름, `observe.sh` (삭제 전)와 `observe-memory.sh` (삭제 전), [README.md](../../../README.md)의 사용법. 후속 승인으로 현재 존재하는 7개 증거 폴더의 이름과 이를 가리키는 문서 경로를 갱신한다. 기존 CPU·교착 스크립트, 메모리 자동 비교, 관제 도구와 과거 증거 파일 내용은 변경하지 않는다.
- 위임: Implementer GPT-6 Sol / Medium의 구현·리뷰 수정·시각 접두어 변경 결과를 회수했다. 사용자 실제 실행 전에는 기능 검증 완료로 표시하지 않는다.
- 결과 위치: [독립 리뷰·수정 재검토](../reviews/REVIEW-TASK-005.md). 최초 Major-1·Minor-1은 사용자의 “수정해” 승인으로 `observe-memory.sh` 한 파일을 보완하고 독립 재검토에서 정적 해결·새 finding 없음. 추가 리뷰 SKIP. 앱·스크립트 실제 실행은 하지 않았다.
- 후속 결과: 당시 7개 폴더를 매핑대로 이동했고 Implementer가 26개 파일의 상대 경로·SHA-256 전후 일치를 보고했다. [후속 독립 리뷰](../reviews/REVIEW-TASK-005-TIMESTAMP-MIGRATION.md)는 시각·설정 및 새 문서 링크 92개를 확인했고 Critical/Major/Minor가 없었다. 이동 전 manifest 원본이 리뷰어에게 없어 해시 일치는 독립 재검증하지 못했다. 첫 Reviewer 호출은 사용량 한도로 실패했고 같은 지정 모델의 새 Reviewer 재시도에서 결과를 회수했다.
- 사용자 실행의 [17:40:57 앱 로그](../../../runs/261027-174057_512_40_false-kz262f/app.log)에서 시각·세 설정을 담은 새 경로와 부트 표식은 확인했다. 이 원본에는 `memory-observation.txt`가 없어 공통 `observe.sh`·시간 제한 메모리 mode 검증으로 확대하지 않는다.
- 다음 행동: 공통 명령의 mode별 실제 호출·반환값, 메모리 관측의 RUNNING 시간 만료 또는 EXITED 결과와 수동 앱 종료 후 포트 해제를 사용자 실행으로 확인한다. 사용자 별도 `memory-test.sh`·`kill-agent-leak.sh`와 `run-memory-comparison.sh` 설정 변경은 TASK-005 범위 밖으로 보존한다.

## Requirements

- [MISSION §2·§4](../MISSION.md), [REQ-002~004](../REQUIREMENTS.md)의 서로 다른 증거 수집을 쉽게 실행하도록 지원한다. 폴더 이름이나 명령 mode는 실제 장애 진단 결과가 아니다.
- 메모리 단일 실행은 설정·PID·앱 로그와 시간별 물리 메모리 RSS 및 생존/종료 상태를 남겨 이후 두 설정을 비교할 수 있게 한다.

## Constraints

- 기존 `run_dir`과 `AGENT_LOG_DIR`의 같은 경로 관계, 기존 로그 파일 내용·형식, 고유한 디렉터리 생성과 원본 보존을 유지한다.
- 폴더명은 `YYMMDD-HHMMSS_MEMORY_LIMIT_CPU_MAX_OCCUPY_MULTITHREAD-XXXXXX` 순서이며 `run-`은 넣지 않는다. 실행 시각을 이름 맨 앞에 두어 이름순으로 시간 순서가 드러나게 한다. 값 표기는 동등한 입력이 같은 이름 요소로 보이게 정규화하되 앱에 전달하는 원래 설정은 유지한다.
- 관측 시간이 끝나면 관제 수집만 끝내고 앱을 자동 종료하지 않는다. 앱이 이미 종료됐는지, PID·포트가 남았는지 사용자에게 알린다. 앱의 자연 종료와 관측 시간 만료를 구분한다.
- 사용자 실행·실제 테스트는 사용자가 담당한다. 불필요한 dependency나 기존 세 도구의 대규모 통합은 하지 않는다.

## Scope

- [prepare-env.sh](../../../prepare-env.sh): 설정 기반의 고유 실행 폴더 이름.
- 후속 승인 당시 존재한 7개 실행 증거 폴더의 이름을 동일 형식으로 바꾸고 기존 로그 내용의 바이트를 보존한다. 해당 폴더를 가리키는 저장소 문서 링크·설명은 새 이름으로 맞춘다. 과거 실행 당시의 옛 경로는 이 TASK에 매핑을 남긴다.
- `observe.sh` (삭제 전): `memory`, `cpu`, `deadlock` mode와 각 mode의 인자를 받는 단일 사용자 진입점.
- `observe-memory.sh` (삭제 전): 정해진 시간의 메모리 단일 실행 관측.
- [README.md](../../../README.md): 새 명령과 설정·폴더 형식, 종료 및 기존 도구 관계 안내.

## Out of Scope

- 앱 자동 종료, 과거 증거 파일 내용·관측 수치 변경, 현재 존재하지 않는 오래된 증거 링크 변경, 기존 메모리 자동 비교의 동작 변경, 제공 바이너리·Harness 공통 규칙 수정.
- CPU 급상승·Watchdog 입증, 새 메모리 비교의 결과를 실행 전에 가정하거나 기존 보고서 완료 상태를 바꾸는 일.

## Acceptance Criteria

- [ ] 예: `bash ./observe.sh memory 128 40 false 60`, `bash ./observe.sh cpu 512 40 false 60`, `bash ./observe.sh deadlock 512 40 true 60`으로 각각 관측 종류를 선택할 수 있다.
- [ ] 새 실행은 예: `runs/261027-183000_128_40_false-Ab12Cd`에 저장된다. 이름순으로 실행 시각이 정렬되며 동일한 세 설정의 반복 실행도 기존 폴더를 덮어쓰지 않는다.
- [x] 후속 승인 당시 존재한 7개 증거 폴더는 아래 매핑대로 이동했다. Implementer가 26개 원본 파일의 상대 경로·해시 전후 일치를 보고했고, 독립 리뷰는 새 경로 링크 92개·시각·설정·로그의 옛 절대 경로 보존을 확인했다. 이동 전 해시 목록의 독립 검증은 수행하지 못했다.
- [ ] 메모리 관측은 앱이 계속 실행해도 지정 시간이 되면 수집을 마치고 증거 경로와 PID·포트 상태를 알려준다. 앱은 남긴다.
- [ ] 기존 CPU·교착 관측과 메모리 자동 비교의 직접 호출을 보존한다. 이름 변경된 기존 증거 경로는 새 경로로 문서 링크를 갱신하고 옛 경로 매핑을 남긴다.
- [ ] 잘못된 mode·인자는 앱을 시작하지 않고 실패를 알린다. 실행 후 수집 실패나 부트 실패는 성공으로 표시하지 않는다.
- [ ] 정적 self-check와 REQUIRED 독립 리뷰 후 사용자 실제 실행 결과로 동작을 확인한다.

## Implementation Notes

- 기존 메모리 자동 비교는 `monitor.sh`의 자연 종료 대기에 의존하므로 40% 실행에는 그대로 연결하지 않는다. 메모리 mode는 일정 시간 수집 후 상태를 보고하는 독립 경로다.
- 사용자가 직접 앱을 종료하므로 종료된 실행과 관측 종료 시점에 살아 있는 실행의 생존 시간을 같게 취급하지 않는다.
- 과거 경로 매핑(현재 작업 공간에 존재하는 폴더만):

| 당시 폴더 이름 | 변경할 폴더 이름 |
| --- | --- |
| `run-2026-10-26_16-01-54-2PYjC0` | `261026-160154_512_80_false-2PYjC0` |
| `run-2026-10-26_16-31-56-69clnq` | `261026-163156_512_80_false-69clnq` |
| `run-2026-10-26_16-38-22-JtWmJF` | `261026-163822_512_80_false-JtWmJF` |
| `run-2026-10-26_17-54-55-kFiIRQ` | `261026-175455_512_40_true-kFiIRQ` |
| `run-2026-10-26_18-00-02-1munWl` | `261026-180002_512_40_false-1munWl` |
| `run-2026-10-27_15-59-44-5osiuy` | `261027-155944_512_80_false-5osiuy` |
| `run-2026-10-27_16-13-41-binP1r` | `261027-161341_512_40_false-binP1r` |

  첫 네 폴더는 사용자 후속 승인 직전 공유 작업 공간에서 이미 `512_...-식별자` 형태로 바뀌어 있었으므로, 실제 rename은 그 이름을 출발점으로 삼았다. 앱 로그 첫 줄의 `launch_local`과 14행 설정을 대조했다. 당시 로그에 인쇄된 옛 절대 경로는 rename 후 현재 위치를 나타내지 않는 역사적 출력이다. 이름의 시각은 초 단위이므로 같은 초 안에 만든 실행끼리는 6자리 임의 접미사의 이름순이 시작 순서를 보장하지 않는다.
