## Major

### Major-1 — 저장된 top 필터로 앱 PID가 빠져도 전체 수집 완료로 표시할 수 있습니다

- 위치: `run-cpu-observation.sh` (삭제 전) top 시작 65행, 완료 검사 170~176행; [README](../../../README.md) CPU 관측 절 107~109행.
- 근거: top 호출은 배치·간격·프레임 수·폭만 지정합니다. 사용자 설정에 저장된 `Other Filter` 또는 최대 표시 태스크 제한을 해제하거나 탐지하지 않습니다. 헤더의 필수 열과 전체 프레임 수가 맞고 어떤 프로세스든 한 행 이상 있으면 완료 검사를 통과합니다. `ps -e` 관계표는 별도로 전체를 저장하지만 누락된 PID의 구간 `%CPU`는 보충하지 않습니다.
- 발생 조건·영향: 사용자가 top에 `COMMAND=...` 같은 다른 프로세스 포함 필터 또는 소수 태스크 표시 제한을 저장해 두었고 그 조건을 만족하는 프로세스가 있는 경우입니다. launcher·선택 자식·추가 후손의 top 표본이 제외되어도 종료 코드 0과 `Observation finished`가 나올 수 있습니다. README의 전체 프로세스 CPU 표 설명과 달라지며 이번 도구의 목적인 앱 관련 PID의 관측 누락 검토를 잘못 해석할 수 있습니다. 이는 실제 재현 결과가 아닌 코드와 설정 동작에서 도출한 위험입니다.
- 최소 수정 방향: 사용자 설정 파일을 변경하지 않는 범위에서 수집에 적용되는 표시 제한을 제거하거나, 지원하지 않는 필터·태스크 제한 설정을 확인하여 수집 실패로 반환하세요. 최소한 앱 PID가 빠진 결과를 전체 수집 성공으로 확정하지 않아야 합니다. 표시 모드 변경이나 CPU 고부하 재현 보장은 요구하지 않습니다.

### Major-2 — ENVIRON이 필수 열 앞에 있으면 공백 분리가 CPU·TIME 열을 오염시킬 수 있습니다

- 위치: `run-cpu-observation.sh` (삭제 전) 공백 분리 82행, 헤더·COMMAND 검사 103~120행, 행 추출·저장 132~140행.
- 근거: 헤더의 토큰 인덱스를 각 행의 공백 분리 토큰 인덱스로 사용합니다. 공백을 포함할 수 있는 선행 열은 `COMMAND`만 거부합니다. top은 `ENVIRON` 필드도 제공하며 프로세스 환경변수를 표시합니다. 해당 열을 PID·%CPU·TIME+ 앞이나 사이에 배치한 사용자 설정은 현재 검사에서 거부되지 않습니다. `%CPU`·`TIME+` 값은 비어 있는지만 확인합니다.
- 발생 조건·영향: 예를 들어 `PID ENVIRON %CPU TIME+ COMMAND` 순서에서 ENVIRON 값에 공백이 있으면 이후 토큰 위치가 밀립니다. PID는 정상적으로 인식되어도 환경변수 토큰 또는 다른 값이 cpu_percent·cpu_time으로 저장될 수 있습니다. 관측 수치가 손상되고 환경변수 일부가 증거 파일에 들어갈 위험도 있습니다. 실제 환경변수나 credential을 읽거나 재현하지 않았습니다.
- 최소 수정 방향: 필수 열 앞에 공백을 포함할 수 있는 ENVIRON 등 지원하지 않는 가변 필드가 있으면 명확히 실패시키거나, 필수 열을 안전하게 추출할 수 있는 제한된 레이아웃을 사용하세요. 기존 COMMAND 검사를 같은 원칙으로 보완하는 범위면 충분하며 범용 top 파서를 새로 만들 필요는 없습니다.
