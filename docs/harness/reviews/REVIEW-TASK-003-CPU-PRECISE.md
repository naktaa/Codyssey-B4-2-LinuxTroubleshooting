## Minor

### Minor-1 — Ctrl+C 후 앱 수명 안내가 호출 방식에 따라 다릅니다

[README.md](../../../README.md)의 관제 설명(108행)은 Ctrl+C로 중단해도 앱이 종료되지 않는다고 안내합니다. 그러나 [monitor.sh](../../../monitor.sh)의 설정값 호출은 중단 상태에서도 `kill-agent-leak.sh`를 호출해 앱 정리를 수행합니다(296–301행). 사용자가 3/4인자 공통 관측을 중단하고 같은 앱을 계속 관찰하려 할 때 예상과 달리 앱이 종료될 수 있습니다. README의 해당 문장을 2인자 PID/CSV 호출에 한정하고, 설정값 호출의 정리 동작을 함께 명시하는 것이 최소 수정입니다.

## Good

- Good-1: [cpu_precise.c](../../../cpu_precise.c)의 `main`은 앱 PID의 프로세스 CPU clock을 읽고(216–225행), 100ms 표본과 독립된 약 1초 경과 구간을 각각 계산합니다(341–364행). 1초 미완성 구간을 종료 시 새 표본으로 추가하지 않습니다(372–380행).
- Good-2: [cpu_precise.c](../../../cpu_precise.c)의 `record_sample`은 양수 표본을 지연 기록하고, 정확히 0인 표본에서 마지막 양수 행에 단순 합을 쓴 뒤 빈 줄로 그룹을 끝냅니다(127–150행). 종료·신호 시 남은 그룹도 flush합니다(372–380행).
- Good-3: [cpu_precise.c](../../../cpu_precise.c)의 `main`은 CSV 생성 전 예상 시작 tick을 확인하고(208–231행), 표본의 CPU clock 읽기 전후에도 동일성을 확인합니다(301–340행). `open_csv`는 `O_EXCL`로 기존 CSV를 보존합니다(119–125행).
- Good-4: [monitor.sh](../../../monitor.sh)는 실행별 `run_dir`의 숨김 경로로 컴파일하고 앱 PID·시작 tick을 C 수집기에 전달합니다(180–208행). 컴파일 실패에도 앱 정리 경로에 도달하며, 시작한 수집 자식을 회수한 뒤 정리합니다(257–303행). 성공 경로의 명시적 stdout 출력은 없고 오류는 stderr로 보냅니다.

## 정적 검토 한계

정상 수집, 대상 환경의 프로세스 clock 지원, 실제 신호·스케줄링 경합, 컴파일 실패·디스크 쓰기 실패 시 결과는 실행 검증하지 않았습니다. 정적 검토에서 Critical/Major를 찾지 못한 사실은 실행 성공이나 CPU 과점유·Watchdog 증거 확보를 뜻하지 않습니다. 관련 파일·데이터 위험은 새 CSV의 배타적 생성과 실패 시 부분 증거 보존을 확인했습니다. C에는 동적 할당이나 수동 포인터 해제 경로가 없으며, 검토한 고정 버퍼와 파싱 경계에서 확인된 메모리 안전 문제는 없습니다.
